\noindent  A diagnostic trace is an execution record: it captures what happened during a particular run,\par
\noindent including tool responses, stochastic environment observations, causal orderings, and interme-\par
\noindent diate model outputs. Removing a trace may be irreplaceable if the underlying tool response\par
\noindent was non-deterministic, the external environment has changed, or the causal ordering was never\par
\noindent logged.\par
\noindent  This distinction is fundamental: removing a KV cache does not delete a diagnostic trace\par
\noindent unless the trace is co-located with the cache and no independent copy exists. The two objects\par
\noindent are stored in different subsystems, consumed by different layers, and retained under different\par
\noindent policies. Their resource budgets can overlap but need not.\par

\noindent 6.2 When Is the Conflict Real?\par
\noindent For a serving-side state object i and a diagnostic horizon T , define three events:\par
\noindent  • Ni (T ): a later diagnosis needs information uniquely carried by object i.\par
\noindent  • Di (T ): object i’s relevant information is discarded before the diagnostic horizon.\par
